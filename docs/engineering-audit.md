# Engineering audit tracker

One table per priority for every finding raised on branch `feat/accounts-durability-operations` (base `4ff70f1`). The sources are:

- the five phase-2 audits: A database and transactions (`DB-`), B authentication and security (`SEC-`), C frontend and mobile scanning (`UX-`), D product (`PROD-`) and E infrastructure (`INF-`);
- the production audit of 2026-11-07 ([production-audit-2026-11-07.md](production-audit-2026-11-07.md), findings `PA-1` to `PA-10`);
- the five known production findings in the project brief (`BRIEF-1` to `BRIEF-5`);
- findings the orchestrator raised during integration (`ORCH-`);
- the static security review of the accounts code, findings R1 to R11 (`SR-01` to `SR-11`). The review read the code only; it ran no proof-of-concept requests. Its severities map to priorities as Medium → P1, Low → P2, Info → P3.

When audits overlap, the tracker keeps one ID and lists the others as aliases. The duplicate takes the higher severity.

**Priorities**, as defined in the brief:

- **P0**: lost admissions, duplicate admission, authorization failures, destructive mistakes.
- **P1**: unreliable scanning, inadequate access control, deployment failure, key user journeys.
- **P2**: reporting, organizer features, frontend polish, performance.
- **P3**: experimental or informational.

**Assigned agent** is the audit area that owns the fix: A (DB), B (Security), C (Frontend), D (Product), E (Infra) or Orchestrator. The orchestrator wrote the server changes; the client and infrastructure changes came from the area agents.

**Status** takes one of these values:

- **Fixed**: the code is on the branch and is covered by a named test that has been run, or by a recorded check. Where no automated test exists, the Regression tests column says so.
- **Fixed (pending verification)**: the code is on the branch, but its regression test, CI job or deployment check has not yet been run and recorded, or no test exercises the changed path yet. The reason is given after the status.
- **Deferred**, **Accepted risk** or **Not reproduced**: each comes with its reason or evidence.

A row can carry two statuses separated by a semicolon when part of the finding is fixed and the rest is accepted or deferred.

Test results are not repeated here; they are in [test-matrix.md](test-matrix.md). As of this writing: the full Vitest suite passed on Windows after the security-review fixes and their regression tests (21 files, 256 passed, 1 skipped); `tests/migration.test.ts` and `tests/recovery.test.ts` passed on Windows and on Linux in Docker; `tests/concurrency.test.ts` passed; Playwright passed on `chromium`, `firefox`, `webkit` and `mobile-chrome`; `tests/vercel-config.test.ts` passed; Vercel preview deployment `gatepass-34awy9su7` built and answered `/api/health` with the preview 503 body; the CI `docker-run` steps passed when run locally, and GitHub Actions has not yet reported a result for this branch.

"Current behavior" describes the code at `4ff70f1` unless stated otherwise. Line references point at the branch as of this writing.
